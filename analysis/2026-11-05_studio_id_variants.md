# ID студии при смене хозяина и названия: три варианта (05.11.2026)

Это материал, показанный Алексею до выбора. Решение — `BRIDGE_LIGHT_PLAN.md` §13. Подпись: Event OS-1 (eventos-1). Факты — со ссылками, выводы помечены.

## Что сломалось

- Адрес студии = `pl` + мобильный номер, решено 03.09 (`BRIDGE_LIGHT_PLAN.md` §9). Light Plan считает его сам из номера в карточке (`BRIDGE_BRONIOS.md` §11.10), API ходит по нему (`§11.1`).
- В справочнике Алексея (`REPORT_2026-11-04.md`): единица — место; прежние названия отдельно; одно название на разных адресах — филиалы; 30 групп студий делят один номер.
- Вывод (не слова Алексея): номер ломается тремя способами — смена хозяина, один хозяин на несколько мест, отсутствие мобильного. В других городах 463 из 1467 записей пока без телефона (нет страницы StudioGo), у 54 страница есть, а номера нет. Сколько найденных номеров мобильные, не измерено. Кроме того, `pl` + номер — это номер с префиксом: ID в публичных файлах раскрывает телефон, а отчёт держит номера вне публичного репозитория.

## Пять понятий

| Понятие | Меняется? | К нему относится | Ключ |
|---|---|---|---|
| Место (здание + этаж/офис) | почти нет; переезд = другое место | адрес, часовой пояс, свет через залы | номер места |
| Зал | добавляют, архивируют, переименовывают | окна, азимут, цены, календарь, брони | номер зала внутри места (`BRIDGE_BRONIOS.md` §10.5) |
| Название / бренд | да; одно название бывает на нескольких адресах | поиск, вывеска | не ключ; список имён с датами |
| Хозяин / оператор | да (продажа, новое ИП) | подписка, токены, календарь, клиенты, памятка, права | не адрес (§6); описание + люди с `id` |
| Контактный телефон | да | звонок, код подтверждения | не ключ; поле с датами |

## Варианты

1. **Личный ID администратора (или хозяина).** Плюс: ничего нового. Минус: администраторы меняются чаще всех; один хозяин с несколькими студиями получает один ID на несколько мест; продажа рвёт историю.
2. **Оставить `pl` + мобильный и залатать** (цепочка «прежний → новый адрес», суффикс для общего номера). Плюс: уже решено, считается на телефоне без сервера, два фотографа независимо получают один адрес. Минус: цепочку кто-то должен писать, суффикс ломает чистое вычисление, студии без мобильного остаются без адреса, номер виден в ID, перевыданный номер отдаёт чужой адрес.
3. **Номер места выдаёт справочник.** Плюс: выдерживает всё из списка Алексея, история привязана к месту, в публичных файлах нет телефонов, как у реестров организаций (LEI/DUNS: назначает держатель реестра, §6). Минус: нужен тот, кто выдаёт и склеивает дубли; адрес на телефоне не вычислить (нужна локальная копия справочника, полевой режим §11 её и так требует); меняет решение 03.09.

**Выбрано: вариант 3** (Алексей, карточка 05.11.2026, «Ключ — место»).

## Слабые места варианта 3

1. Дубли: нужна склейка с переадресацией старого номера.
2. Что такое «то же место»: этаж, офис, перепланировка, один вход на два помещения; сомнительное — «кандидат», решает человек.
3. Один писатель номеров, пока справочник — файлы.
4. Власть реестра: каталог не маркетплейс (§22), номер выдаётся без ранжирования и платы; спор о правах на место решает человек-оператор справочника (кто это — вопрос Алексея).
