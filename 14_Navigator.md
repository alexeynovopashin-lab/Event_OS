1. Purpose
Navigator — пользовательский слой Event OS, который превращает вычисленный контекст в понятное человеку сопровождение.
Если:
Graph знает структуру события;
Timeline знает последовательность;
Context Engine знает, что важно сейчас;
то Navigator отвечает на вопрос:
Что мне нужно знать и делать прямо сейчас?
Navigator не является отдельной системой хранения данных.
Он является интерфейсом над Context Engine.
2. Core Concept
Navigator работает по принципу навигации.
                    EVENT
                      │
                      ▼
                    GRAPH
                      │
                      ▼
                   TIMELINE
                      │
                      ▼
                CONTEXT ENGINE
                      │
                      ▼
                  NAVIGATOR
                      │
                      ▼
                    USER
Navigator не показывает пользователю всю систему.
Он ведет его через событие.
3. Navigation Principle
Автомобильный навигатор знает весь маршрут, но не заставляет водителя изучать карту целиком.
Он сообщает:
Вы здесь.

Через 150 м направо.

После поворота — прямо.

Через 2 км — следующий маневр.
Event OS работает аналогично.
Фотографу не нужно постоянно видеть весь план свадьбы.
Ему необходимо знать:
Сейчас — сборы.

Через 20 минут выезд.

Машина стоит у входа.

Следующая точка — загородный дом.

4. Navigator Is Not a Dashboard
Dashboard показывает состояние системы.
Navigator показывает путь.
Это принципиальное различие.
Dashboard
┌─────────────────────────────┐
│ Projects       12           │
│ Tasks          37           │
│ Messages       18           │
│ Payments        5            │
│ Contractors    24            │
└─────────────────────────────┘
Navigator
СЕЙЧАС

Съёмка в усадьбе.

До выезда 18 минут.

Машина ожидает у входа.

⚠ Маршрут изменён.

Следующий шаг →
Второй интерфейс соответствует философии Event OS.
5. Navigator States
Navigator имеет несколько основных состояний:
WAITING
APPROACHING
CURRENT
CHANGED
BLOCKED
COMPLETED

5.1 WAITING
До следующего события еще достаточно времени.
Пользователь получает минимальный контекст.
Следующая сцена

Церемония

14:00
5.2 APPROACHING
Событие становится актуальным.
Контекст постепенно раскрывается.
Через 45 минут

Церемония

Локация: усадьба
Выезд: через 20 минут
5.3 CURRENT
Сцена активна.
Показывается полный рабочий контекст.
СЕЙЧАС

Церемония

Усадьба

14:00–14:40

Фотограф:
слева от арки

Следующее:
групповые фотографии
5.4 CHANGED
Произошло изменение, влияющее на пользователя.
Изменение получает высокий приоритет.
⚠ ИЗМЕНЕНИЕ

Церемония перенесена
в банкетный зал.

Начало: 14:20

Подробнее →
5.5 BLOCKED
Следующий шаг невозможно выполнить по первоначальному плану.
Navigator должен не просто сообщить о проблеме, но и показать доступный вариант продолжения.
⚠ МАРШРУТ ЗАБЛОКИРОВАН

Дорога на площадку перекрыта.

Альтернативный маршрут:
+8 минут

Выезд: 13:42
5.6 COMPLETED
Сцена завершена.
Navigator переводит внимание пользователя дальше.
✓ Церемония завершена

Следующая сцена:

Прогулка

Через 10 минут
6. Next Best Context
Navigator всегда пытается определить следующий релевантный контекст.
Условно:
Next Context =
f(
    Current Scene,
    Next Scene,
    Role,
    Time,
    Dependencies,
    Changes
)
Следующим контекстом может быть:
информация;
предупреждение;
маршрут;
контакт;
документ;
задача;
изменение.
Следующий контекст не обязательно является действием.
7. Next Action
Navigator может предложить пользователю действие.
Например:
Подтвердить маршрут
Позвонить водителю
Открыть shot list
Подтвердить изменение
Но система не должна превращать каждую ситуацию в задачу.
Если действие не требуется, Navigator просто сообщает необходимую информацию.
8. Information Before Action
Сначала пользователь должен понять ситуацию.
Только после этого система предлагает действие.
Неправильно
[Изменить маршрут]
Правильно
⚠ Дорога перекрыта.

Старый маршрут больше недоступен.

Новый маршрут занимает +8 минут.

[Открыть маршрут]

Navigator раскрывает информацию постепенно.
Например:

Следующий момент:
кольца
Пользователь не получает всю информацию заранее.
10. Role-Based Navigation
Один Timeline порождает разные Navigator Views.

    ContextEngine --> Driver
    ContextEngine --> Florist

Каждая роль получает собственный маршрут через одно событие.

14. Client Navigator
Молодожены получают максимально упрощенный маршрут:

Клиент не должен видеть внутреннюю операционную структуру команды.
15. Navigator and Permissions
Navigator не расширяет права доступа.
Он работает только с теми объектами, к которым пользователь имеет доступ.
Permissions
     │
     ▼
Available Graph
     │
     ▼
Context Engine
     │
     ▼
Navigator
Нельзя получить через Navigator информацию, которая недоступна пользователю напрямую.
16. Navigator and Notifications
Notification и Navigator — разные механизмы.
Notification сообщает:
Что-то изменилось.
Navigator отвечает:
Что это означает для тебя сейчас?
Например:
Notification:

⚠ Маршрут изменён.
После открытия:
Navigator:

Старый маршрут больше недоступен.

До площадки:
24 минуты.

Новый выезд:
13:36.

[Открыть маршрут]
17. Notification Fatigue
Navigator должен уменьшать количество уведомлений.
Не каждое изменение требует push-уведомления.
Если изменение не влияет на пользователя сейчас, оно может оставаться внутри контекста.
Push необходим, если:
изменение критично;
требуется действие;
пользователь должен узнать об изменении до следующей сцены.
18. Navigator and Chat
Navigator не заменяет чат.
Он использует коммуникацию как часть контекста.
Например:
⚠ Организатор сообщил:

«Начинаем на 20 минут позже
из-за дождя».
Пользователь видит сообщение непосредственно в контексте изменения.
Ему не требуется искать его среди сотен сообщений.
19. Navigator and Documents
Если документ становится актуальным, Navigator может предложить его.
Например:
Через 20 минут:

Монтаж декораций.

Схема площадки обновлена.

[Открыть схему]
20. Navigator and Weather
Погода не должна постоянно занимать экран.
Она появляется только тогда, когда влияет на текущий маршрут или сцену.
Сейчас:
облачно

Через 40 минут:
дождь 70%

⚠ Outdoor Ceremony
имеет риск переноса.
Система не должна самостоятельно менять план только на основании прогноза.
21. Navigator and Light
Для фотографа Navigator может учитывать свет:
Через 18 минут:

Golden Hour

Продолжительность:
42 минуты

Рекомендуемая позиция:
парк
Система не заставляет фотографа следовать рекомендации.
Она предоставляет контекст.
22. Navigator and Location
Геолокация является дополнительной функцией.
При разрешении пользователя Navigator может сравнивать:
Current Location

+

Expected Location

+

Current Time
И определять:
On time
или:
Running late
Отсутствие геолокации не должно ломать навигацию.
23. Navigator and Offline Mode
Navigator должен продолжать работать без сети с последним синхронизированным контекстом.
Минимально доступно:
текущая сцена;
следующая сцена;
время;
адрес;
маршрут;
контакты;
локально сохраненные документы;
последние изменения.
После восстановления сети контекст пересчитывается.
24. Navigator on Desktop
На компьютере Navigator не должен занимать весь интерфейс.
Desktop предназначен для управления проектом.
Navigator может существовать как:
боковая панель;
preview текущей сцены;
live status;
режим контроля мероприятия.
Организатор должен иметь возможность видеть одновременно:
Timeline

+

Current Context

+

Project Graph
25. Navigator on Mobile
На телефоне Navigator является главным рабочим режимом.
Основной экран должен быть максимально простым.

26. Navigator Modes
Navigator может иметь несколько режимов.
Standard
Обычный режим сопровождения.
Focus
Только текущая сцена и ближайший контекст.
Route
Навигация между локациями.
Changes
Последние изменения проекта.
Full Timeline
Переход к полной временной модели.
Emergency
Критические изменения и проблемы.
27. Emergency Context
Emergency не означает чрезвычайную ситуацию в буквальном смысле.
Это состояние, при котором обычный маршрут больше не работает.
Например:
площадка закрыта;
транспорт задерживается;
артист отменился;
погода изменилась;
сцена перенесена.
Navigator должен перейти от:
Follow Route
к:
Adapt Route
28. Adaptation
Ключевая функция Navigator — адаптация.
Если реальность отличается от плана:
Plan

↓

Reality

↓

Difference

↓

New Context

↓

New Route
Event OS не пытается сохранить первоначальный план любой ценой.
Она помогает команде адаптироваться.
29. No Forced Automation
Navigator не должен самостоятельно:
менять расписание;
отменять сцены;
уведомлять всех участников;
менять роли;
менять финансовые статусы.
Он может предложить изменение.
Решение принимает человек.
30. Navigator as a Contract
Navigator создает единый контракт между человеком и системой.
Система обещает:
Я покажу тебе то, что тебе необходимо знать сейчас.
Пользователь может доверять Navigator, потому что ему не нужно самостоятельно контролировать сотню объектов проекта.
31. Success Criteria
Navigator считается успешным, если пользователь может открыть приложение в любой момент и за несколько секунд ответить:
Где я?
Что происходит?
Что изменилось?
Что мне делать?
Куда двигаться дальше?
Если пользователь после открытия приложения начинает самостоятельно искать информацию, Navigator не выполняет свою функцию.
32. Design Rules
Do not show the whole project
Пользователь не должен постоянно видеть весь граф.
Show the next relevant context
Главное — ближайший значимый контекст.
Explain changes
Изменение без объяснения создает неопределенность.
Give options, not commands
Система предлагает.
Человек решает.
Keep the route understandable
Пользователь всегда должен понимать:
Current
→ Next
→ Later
Never hide critical changes
Критическое изменение должно быть заметно независимо от текущего экрана.
Reduce cognitive load
Navigator существует для того, чтобы человеку не приходилось держать проект в голове.
33. Relationship to Other Components
Navigator не заменяет остальные компоненты системы.

flowchart TD
    Event[Event] --> Graph[Graph Model]
    Graph --> Timeline[Timeline Canvas]
    Timeline --> Context[Context Engine]
    Context --> Navigator[Navigator]

    Navigator --> User[User]

    Graph --> Permissions[Permissions]
    Permissions --> Context

    Graph --> Changes[Changes]
    Changes --> Context

    Graph --> Weather[Weather]
    Weather --> Context

    Graph --> Communication[Communication]
    Communication --> Context

Ответственность компонентов разделяется следующим образом:
Компонент	Ответственность
Graph Model	Хранит структуру и связи события
Timeline Canvas	Представляет событие во времени
Context Engine	Вычисляет релевантный контекст
Permissions	Определяет доступные пользователю данные
Navigator	Представляет контекст пользователю
Notification System	Доставляет критические изменения
AI	Может анализировать контекст и предлагать рекомендации
34. Navigator Statement
Navigator — это интерфейс сопровождения Event OS. 
Он превращает сложный граф мероприятия в понятный персональный маршрут, 
показывая каждому участнику только тот контекст, который необходим ему сейчас, 
и помогая адаптироваться, когда реальность расходится с первоначальным планом.
