````markdown
## 1. Purpose

AI is an optional intelligence layer of the system.

The system must remain fully functional without AI.

AI does not replace:

- the project model;
- the graph;
- the timeline;
- the context engine;
- permissions;
- communication;
- human decisions.

AI operates on top of structured project data and helps users understand, prepare, coordinate and act.

---

# 2. Core Principle

> **AI should make the system easier to use, not make the system dependent on AI.**

The architecture must work:

```text
WITH AI
````

and:

```text
WITHOUT AI
```

with the same underlying project state.

---

# 3. AI Is Not the Operating System

The product is not an AI chatbot with wedding-planning features.

It is an operational system with an optional AI layer.

```text
┌─────────────────────────────┐
│             AI              │
│ summaries / suggestions /   │
│ reasoning / assistance      │
└──────────────┬──────────────┘
               │
┌──────────────▼──────────────┐
│       Context Engine        │
└──────────────┬──────────────┘
               │
┌──────────────▼──────────────┐
│        Project Graph        │
└──────────────┬──────────────┘
               │
┌──────────────▼──────────────┐
│        Project State        │
└─────────────────────────────┘
```

AI should not become the source of truth.

---

# 4. Source of Truth

The source of truth is structured project state.

Examples:

```text
Event
Time
Location
Person
Role
Assignment
Status
Document
Decision
Job
Payment Status
```

AI can interpret these objects.

AI must not silently redefine them.

---

# 5. AI Must Respect the Graph

The project graph is the primary source of relationships.

For example:

```text
Ceremony
   │
   ├── Location
   │
   ├── Photographer
   │
   ├── Videographer
   │
   ├── Coordinator
   │
   └── Driver
```

If the ceremony changes location, AI should use graph relationships to determine potential impact.

It should not guess who might be affected.

---

# 6. AI Must Respect Permissions

AI has no additional authority beyond the user.

If a user cannot access an object manually, AI should not reveal it.

```text
User
 ↓
Permissions
 ↓
Accessible Graph
 ↓
AI Context
```

Never:

```text
User
 ↓
AI
 ↓
Entire Database
```

---

# 7. AI Context

AI should receive the smallest useful context.

The context should be constructed by the Context Engine.

Example:

```text
User:
Photographer

Current project:
Wedding A

Current time:
12:40

Current location:
Preparation venue

Next event:
Ceremony at 13:30

Relevant changes:
Ceremony moved from 13:00 to 13:30

Affected information:
New route
New location
Coordinator contact
```

AI does not need the entire organization's database.

---

# 8. Context Before Prompt

AI requests should preferably be generated from structured context.

Bad:

```text
"Tell the AI everything about this wedding."
```

Better:

```text
Role:
Photographer

Current event:
Preparation

Next event:
Ceremony

Relevant changes:
...

Required action:
...
```

The Context Engine prepares the working set.

---

# 9. AI Should Be Role-Aware

The same project can produce different AI responses for different users.

Example:

### Photographer

```text
Ceremony moved 30 minutes later.
Your portrait session remains unchanged.
New route adds approximately 12 minutes.
```

### Driver

```text
Pickup moved from 12:40 to 13:00.
New destination:
St. Mary's Church.
```

### Organizer

```text
Ceremony moved 30 minutes later.
Affected:
Photographer
Videographer
Driver
Venue
```

The underlying project is identical.

The context is different.

---

# 10. AI Should Be Time-Aware

AI recommendations must consider the current moment.

A problem that is harmless tomorrow may be critical in 20 minutes.

Example:

```text
Tomorrow:
Rain expected during portraits.
```

During the event:

```text
Rain approaching in 18 minutes.
Portrait session should be moved or shortened.
```

---

# 11. AI Should Understand Plan vs Reality

AI must distinguish:

```text
Planned
Estimated
Confirmed
Actual
```

Example:

```text
Planned ceremony:
13:00

Current confirmed time:
13:30

Actual:
Not started
```

AI must not describe planned values as facts.

---

# 12. AI Should Understand Uncertainty

The system may contain uncertain information.

Examples:

```text
Tentative
Estimated
Unconfirmed
Suggested
Unknown
```

AI should preserve that uncertainty.

Bad:

```text
"The ceremony will be outside."
```

when the location is only proposed.

Good:

```text
"Outdoor ceremony is currently proposed but not confirmed."
```

# 13. Primary AI Capabilities

AI capabilities are divided into several categories.

```text
1. Understanding
2. Summarization
3. Navigation
4. Coordination
5. Detection
6. Planning
7. Generation
8. Communication
9. Analysis
```

---

# 14. Understanding

AI helps users understand existing project information.

Examples:

```text
"What is happening today?"

"What changed since yesterday?"

"What's important for me?"

"Why was the schedule changed?"

"What do I need to know before arriving?"
```

---

# 15. Summarization

AI can compress large amounts of information.

Examples:

```text
Project summary
Daily briefing
Role briefing
Meeting summary
Chat summary
Change summary
Document summary
Post-event summary
```

The summary should be generated from structured data where possible.

---

# 16. Role Briefing

A role briefing is a short operational explanation of the project for a specific participant.

Example:

```text
You are the photographer.

Today:
Ivanov + Petrova wedding.

Your work:
10:00–22:00.

Next:
Preparation at 10:00.

Important:
Ceremony moved to 13:30.

Weather:
Rain possible after 16:00.

Coordinator:
Anna — +7 XXX XXX XX XX.
```

The briefing should be short enough to read immediately.

---

# 17. "Middle of the Movie" Briefing

When a participant joins late, AI can generate an onboarding briefing.

Input:

```text
Project state
Timeline
Relevant history
Role
Current time
Changes
```

Output:

```text
What is this project?
What is my role?
What has changed?
What matters now?
What happens next?
Who should I contact?
```

The goal is operational readiness, not historical completeness.

---

# 18. Navigator Assistance

AI can explain the Navigator.

Example:

```text
User:
"Why am I going here?"

AI:
"Because the ceremony location changed yesterday.
Your next assignment starts at 13:30.
The new location is 12 minutes from here."
```

AI explains system state.

It does not replace the Navigator.

---

# 19. Change Detection

AI can help identify meaningful changes in unstructured information.

Sources may include:

* messages;
* documents;
* meeting notes;
* uploaded files;
* emails, where integrated.

Example:

```text
Message:
"Let's move the ceremony to the garden at 13:30."
```

AI can identify:

```text
Potential change:
Ceremony time
13:00 → 13:30

Potential change:
Location
Main Hall → Garden
```

---

# 20. AI Must Not Silently Apply Important Changes

Detected changes should be presented for confirmation when they affect project state.

Example:

```text
I found a possible schedule change.

Ceremony:
13:00 → 13:30

Location:
Main Hall → Garden

Apply changes?
[Confirm]
[Review]
```

---

# 21. Impact Analysis

Once a change is confirmed, the graph can determine affected nodes.

AI may explain the impact.

Example:

```text
Ceremony moved to 13:30.

Potential impact:

Photographer
Videographer
Driver
Venue

No impact detected for:

Retoucher
Florist
Cake delivery
```

The graph determines relationships.

AI explains them.

---

# 22. Conflict Detection

AI can identify potential conflicts.

Examples:

```text
Two events overlap.

A driver cannot physically reach both locations.

Photographer travel time exceeds available gap.

Venue setup time is insufficient.

Two contractors are assigned to simultaneous events.
```

---

# 23. Conflict Detection Must Be Explainable

Bad:

```text
Schedule conflict detected.
```

Good:

```text
Potential conflict:

Photographer leaves Venue A at 14:20.

Next assignment:
Venue B at 14:30.

Estimated travel time:
22 minutes.

The schedule is unlikely to be achievable.
```

---

# 24. AI Recommendations

AI may propose alternatives.

Example:

```text
The portrait session overlaps with the current transfer.

Possible options:

1. Move portraits 20 minutes earlier.
2. Shorten portraits from 40 to 25 minutes.
3. Move portraits to the reception venue.

Option 1 has the smallest impact on the rest of the timeline.
```

AI recommends.

A responsible human confirms.

---

# 25. AI Should Not Make Irreversible Decisions

AI should not independently:

* cancel a contractor;
* change a contract;
* alter financial obligations;
* cancel an event;
* disclose private information;
* send sensitive messages;
* modify critical project state.

unless a future explicit automation system grants that authority and the user has configured it.

---

# 26. AI Communication Assistance

AI may help draft messages.

Examples:

```text
"Write a message to the driver about the new route."

"Tell the photographer the ceremony moved."

"Ask the florist whether setup can start 30 minutes earlier."
```

AI produces a draft.

The user remains responsible for sending it unless explicit automation is configured.

---

# 27. Communication Should Preserve Context

An AI-generated message should be associated with the relevant object.

Example:

```text
Event:
Ceremony

Change:
13:00 → 13:30

Recipient:
Photographer

Message:
"The ceremony has moved to 13:30.
The location remains unchanged."
```

---

# 28. Meeting and Call Summaries

Example:

```text
 ↓
```

# 29. Document Understanding

# 33. Planning Assistance

AI planning should consider:

```text

Venue restrictions
Service duration
People

```

A beautiful timeline that cannot physically happen is useless.

---

# 36. AI + Weather

Weather is an important contextual input for outdoor events.

AI can:

* summarize weather risk;
* identify affected events;
* suggest alternatives;
* prepare communication.

Example:

```text
Rain is expected between 16:30 and 17:20.

Affected:
Outdoor portrait session.

Suggested options:
Move portraits to 15:50
or
Use indoor location.
```

AI should not automatically change the timeline.

---

# 37. AI + Light

For photography-related workflows, AI can use:

* sunrise;
* sunset;
* golden hour;
* blue hour;
* location;
* schedule.

Example:

```text
The planned sunset portraits start 28 minutes after sunset.

Consider moving the session earlier.
```

---

# 38. AI + Navigation

AI can help explain routes and schedule conflicts.

It should not replace dedicated navigation systems.

Example:

```text
The next location is approximately 18 minutes away.

```

# 39. AI + Postproduction

AI can help coordinate long-running postproduction.

Examples:


---

# 40. AI + Client Communication

AI may help prepare:

* reminders;
* status updates;
* delivery messages;
* feedback requests;
* photo book offers;
* follow-up messages.

The system should avoid turning communication into spam.

---

# 41. AI + Sales Opportunities

The system may identify legitimate opportunities based on project state.

Example:

```text
Photos delivered.

Potential next interaction:
Photo book
```

AI may suggest:

```text
"The client has received the gallery.
This may be a suitable moment to offer a photo book."
```

The system should not aggressively automate sales.

---

# 42. AI + Finance

AI may summarize financial status.

Example:


---

# 43. AI Must Respect Financial Boundaries

The system should not:

* process payments;
* initiate acquiring;
* file taxes;
* make accounting decisions;
* claim legal compliance.

AI may organize and explain financial information already present in the project.

---

# 44. AI + Legal Information

AI may help identify:

* missing contract fields;
* dates;
* obligations;
* unusual clauses;
* inconsistencies.

It should clearly distinguish:

```text
Extracted fact
```

from:

```text
AI interpretation
```

and:

```text
Legal advice
```

The system should not present AI output as professional legal advice.

---

# 45. AI Confidence

Where appropriate, AI should communicate confidence.

Possible states:

```text
Confirmed by project data
Derived from project data
Likely
Possible
Needs confirmation
```

Do not use arbitrary numerical confidence scores unless they provide meaningful value.

---

# 46. AI Provenance

Important AI-generated claims should be traceable.

Example:

```text
Ceremony:
13:30

Based on:
Confirmed timeline change
08 Aug, 14:32
```

or:


---

# 47. AI Memory

AI should not create an independent hidden memory of project facts.

Persistent project information belongs in the project graph.

```text
Correct:

User
 ↓
Project State
 ↓
AI

Incorrect:

User
 ↓
AI private memory
```

---

# 48. AI Conversations

An AI conversation may be temporary.

The result of the conversation can become persistent project state only through explicit structured actions.

Example:

```text
User:
"Let's move portraits to 16:00."

AI:
"This conflicts with dinner setup."

User:
"Then 15:30."

AI:
"15:30 is compatible."

[Apply to Timeline]
```

The final state is stored in the project.

---

# 49. AI Should Prefer Actions Over Answers

When the user asks:

```text
"What should I do?"
```

the system should provide:

```text
Situation
Recommendation
Reason
Action
```

Example:

```text
Rain is expected before portraits.

Recommendation:
Move portraits 20 minutes earlier.

Reason:
This preserves the reception schedule.

[Move portraits]
```

---

# 50. AI Should Be Interruptible

The user should always be able to:

* cancel;
* ignore;
* reject;
* edit;
* ask for alternatives.

AI is an assistant, not an authority.

---

# 51. AI Should Not Become Noisy

AI should not constantly generate:

```text
Suggestions
Notifications
Warnings
Summaries
```

without a clear reason.

Silence is preferable when everything is normal.

---

# 52. Exception-Driven AI

The highest-value AI interactions often occur when reality deviates from the plan.

```text
Normal:
No intervention.

Exception:
Analyze.

Impact:
Identify.

Options:
Suggest.

Decision:
Human confirms.

State:
Update.
```

---

# 53. AI Event Loop

The conceptual AI workflow:

```text
1. Observe
2. Understand
3. Identify relevance
4. Detect problem/opportunity
5. Explain
6. Suggest
7. Ask for confirmation
8. Apply
9. Record
```

Not every situation requires every step.

---

# 54. AI Must Never Invent Project State

AI must not fabricate:

* people;
* times;
* payments;
* confirmations;
* contracts;
* locations;
* completed work.

If information is unavailable:

```text
Unknown
```

is an acceptable answer.

---

# 55. AI Should Ask When Necessary

If an action requires information that does not exist:

```text
"What time should the photographer arrive?"
```

AI should ask rather than guess.

---

# 56. AI Should Prefer Existing Data

Before asking the user, AI should check accessible project state.

Example:

```text
Question:
"Where is the ceremony?"

Check:
Timeline
Event
Venue
Documents
Confirmed decisions

Only then ask the user.
```

---

# 57. AI Should Not Search the Entire System Blindly

AI retrieval should be scoped by:

```text
Organization
Project
Role
Permissions
Context
```

This improves:

* privacy;
* speed;
* relevance;
* reliability.

---

# 58. AI Security

AI must follow the same security principles as the rest of the system.

Requirements:

* permission-aware retrieval;
* tenant isolation;
* audit logging;
* controlled external model access;
* sensitive-data protection;
* explicit integration permissions.

---

# 59. External AI Providers

If external AI models are used, the system should define:

```text
What data leaves the system?
Why?
Where is it processed?
How long is it retained?
Who controls it?
```

The product should avoid sending unnecessary project data to external providers.

---

# 66. Read vs Write

AI operations should be divided into:

```text
READ
```

and:

```text
WRITE
```

Read operations can usually be automatic within permissions.

Write operations require stronger controls.

---

# 67. Write Levels

### Level 0 — No persistence

AI only answers.

### Level 1 — Draft

AI prepares content.

### Level 2 — Suggested change

AI proposes structured modification.

### Level 3 — User confirmation

User explicitly applies change.

### Level 4 — Configured automation

A trusted automation may perform predefined low-risk actions.

The system should begin at Levels 0–3.

```text
    ↓
```

Example:


> What could I do?

# 75. AI and the Graph

### AI

Reasons over those relationships.

# 76. AI and Chat

---

# 77. AI and Documents

### Documents

Store authoritative artifacts.

---

# 78. AI and Human Responsibility


# 79. AI Product Principle

The best AI interaction is often invisible.

If the system already knows:

```text
Who
Where
When
Why
What changed
What happens next
```

the user should not have to explain the context to AI manually.

---

# 80. Final AI Principle

> **AI should know the context so the user does not have to explain the context.**

The system already contains the project's memory.

AI's job is to transform that structured memory into:

```text
Understanding
Recommendations
Warnings
Briefings
Actions
```

while preserving:

```text
Truth
Permissions
Human control
Auditability
Reversibility
```
