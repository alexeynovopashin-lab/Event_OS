Проверка живого адреса: `MODE=op yandex/check.sh <адрес>` (в Яндексе работает только `?op=…`, измерено 23.11).

## Маршруты

| Маршрут | Пропуск | Ответы |
|---|---|---|
| `GET /v1/health` | нет | `200 {"ok":true,"core","home","time","api":["devices","avatar"]}` |
| `POST /v1/devices` | нет | `201 {deviceId, pass, idState:"unconfirmed", home}`; `400 bad_id / bad_request / wrong_home` |
| `PATCH /v1/devices/me` | да | `200`; `400 bad_id`; `409 previous_mismatch / id_taken` |
| `DELETE /v1/devices/me` | да | `204` (последнее устройство ID уносит и аватарку) |
| `PUT /v1/me/avatar` | да | `200 {sha256,size}`; `413` > 1 МБ; `415` не JPEG; `422 bad_size / bad_jpeg` |
| `GET /v1/me/avatar` | да | `200` + `ETag`; `304`; `404 none` |
| `DELETE /v1/me/avatar` | да | `204` |
| `POST /v1/avatars/lookup` | нет | **всегда `404 none`** до CORE-05 («Все, кто знает номер» включится после подтверждения номера) |
| `DELETE /v1/me` | да | `204`: все устройства ID, аватарка, пометки «переехал»; повтор тоже `204` |

Пропуск передаётся в заголовке **`X-Core-Pass: <пропуск>`** (дом ru — только так: `Authorization: Bearer` шлюз Яндекса
принимает за свой IAM-токен и отвечает 403, измерено 23.11); `Authorization: Bearer` принимается для других домов.
В Яндексе адрес — `https://functions.yandexcloud.net/<id>?op=<маршрут без /v1/>`.

Везде: `401 bad_pass`, `429 rate_limited` (30 запросов в минуту на пропуск), ошибки — `{"error":"…"}`.
В журнал уходят только маршрут, `deviceId`, код и время.

## Что решено в коде и отличается от инструкции (технические развилки сессии)

1. **Пропуск = `<deviceId>.<32 байта>`**, а не просто 32 байта: устройство находится по ключу, без индекса по хешу.
   Хранится по-прежнему только HMAC. Для приложения пропуск — непрозрачная строка, ничего менять не надо.
2. **Аватарки в YDB**, а не в Object Storage (дом ru): иначе нужны постоянные ключи доступа к хранилищу в настройках функции.
   Розетка хранилища позволяет вынести их позже.
3. **Номер в хранилище не попадает**: только `HMAC(соль, "id:"+ID)` и `HMAC(соль, "avatar:"+ID)`.
4. **Вырезание метаданных вместе с цветовым профилем** (APP2/ICC входит в APP1–APP15): для обычной sRGB-картинки не видно,
   для Display P3 цвета на сервере чуть бледнее. Слово Алексея 23.11: «только вырезать».
5. **Проверка «мобильный номер» на сервере упрощена**: форма E.164, а для +7 после семёрки должна идти 6, 7 или 9
   (городские +7 3xx/4xx/8xx отклоняются). Полная проверка остаётся в приложении. Вывод сессии, не мерено по таблице операторов.
6. **Дом ru принимает только страны +7 и СНГ** (список из `CoreLink.swift`, `id.mjs`); остальные получают `400 wrong_home` —
   их примет дом «мир» (Cloudflare), он позже.
