# Vision

Event OS — это операционная система для управления мероприятиями.

Мы создаем единую цифровую среду, в которой все участники события работают с одним проектом, одним контекстом и одним источником истины.

Платформа должна сопровождать мероприятие от первой встречи с клиентом до завершения постпродакшена.

---

# Industry Today

Сегодня организация мероприятий представляет собой набор разрозненных инструментов.

Типичный проект распределен между:

- Telegram;
- WhatsApp;
- Google Calendar;
- Apple Calendar;
- Excel;
- Google Sheets;
- PDF-документами;
- облачными дисками;
- CRM;
- блокнотами;
- памятью организатора.

Каждый сервис знает только свою небольшую часть проекта.

Ни один не понимает мероприятие целиком.

---

# The Core Problem

Информация существует.

Контекст — нет.

Участники постоянно задают одинаковые вопросы.

- Где сейчас актуальный тайминг?
- Какой маршрут действует?
- Кто подтвердил участие?
- Что изменилось за последние два дня?
- Где лежит последняя версия документа?
- Кому уже сообщили об изменениях?

Практически вся коммуникация строится вокруг восстановления контекста.

---

# Event OS Changes The Model

Мы меняем саму модель организации мероприятий.

Вместо набора отдельных сервисов появляется единая операционная среда.

```
             Event

                │

    ┌───────────┼───────────┐
    │           │           │
People      Timeline     Context
    │           │           │
Communication Documents  Files
    │           │           │
 Finance     Weather     History
```

Каждый элемент существует как часть одного события.

---

# Event-Centric Architecture

В центре платформы находится **Event**.

Не пользователь.

Не организация.

Не подрядчик.

Не клиент.

Событие является источником всех связей внутри системы.

Любой объект имеет смысл только в рамках конкретного мероприятия.

---

# Context-Centric Experience

Большинство систем показывают пользователю информацию.

Event OS предоставляет контекст.

Контекст — это информация, необходимая конкретному человеку в конкретный момент времени.

Система отвечает не на вопрос:

> Что находится в проекте?

Она отвечает на вопрос:

> Что необходимо знать сейчас?

---

# Timeline Is The Workspace

Timeline является основной рабочей поверхностью платформы.

Это не календарь.

Не список задач.

Не расписание.

Timeline представляет собой последовательность сцен мероприятия.

Каждая сцена объединяет:

- время;
- место;
- участников;
- документы;
- сообщения;
- изменения;
- оборудование;
- погоду;
- связанные действия.

Вся работа происходит через Timeline.

---

# Context Navigator

Главным интерфейсом платформы является контекстный навигатор.

Он работает по тем же принципам, что автомобильный навигатор.

Навигатор знает весь маршрут.

Но показывает только следующий необходимый шаг.

Event OS знает весь проект.

Но показывает пользователю только тот контекст, который необходим ему для принятия следующего решения.

---

# Information Should Follow People

Современные системы заставляют пользователя искать информацию.

Event OS доставляет информацию самостоятельно.

Если изменение влияет на пользователя, система сообщает об этом автоматически.

Если изменение не относится к текущей роли пользователя, оно не отвлекает внимание.

---

# Every Role Has Its Own Journey

Каждый участник проходит мероприятие по собственному маршруту.

Фотограф сопровождается от сборов до передачи фотографий.

Видеограф — от съемки до финального монтажа.

Флорист — от монтажа оформления до демонтажа.

Ведущий — от подготовки программы до завершения вечера.

Молодожены — от первой встречи до получения готового материала.

Все работают внутри одного проекта.

Но каждый проходит собственный путь.

---

# Dynamic Context

Контекст изменяется непрерывно.

На него влияют:

- время;
- этап мероприятия;
- изменения проекта;
- местоположение;
- роль пользователя.

Система постоянно пересчитывает, какая информация является наиболее важной.

---

# Beyond The Wedding Day

Для большинства участников мероприятие заканчивается по-разному.

Для ресторана — после завершения банкета.

Для флориста — после демонтажа.

Для ведущего — после окончания программы.

Для фотографа и видеографа работа продолжается еще несколько недель.

Event OS сопровождает полный жизненный цикл проекта.

От первого обращения клиента до завершения постпродакшена.

---

# Platform Principles

Платформа должна быть:

- простой;
- масштабируемой;
- модульной;
- независимой от ИИ;
- независимой от платежных систем;
- независимой от бухгалтерии.

Каждый модуль должен дополнять систему, а не усложнять ее.

---

# Artificial Intelligence

ИИ не является основой продукта.

Все процессы должны работать без него.

ИИ усиливает систему:

- анализирует контекст;
- обнаруживает риски;
- помогает принимать решения;
- подготавливает рекомендации.

Последнее решение всегда остается за человеком.

---

# Long-Term Vision

Через десять лет Event OS должна стать стандартной платформой для управления мероприятиями.

Независимо от масштаба проекта.

Независимо от количества участников.

Независимо от страны.

Пользователь перестает думать о том, где находится информация.

Он работает только с событием.

---

# Vision Statement

Мы создаем не программное обеспечение.

Мы создаем среду, в которой информация самостоятельно приходит к нужным людям в нужный момент времени.

Каждый участник мероприятия получает собственный маршрут, собственный контекст и собственное рабочее пространство, оставаясь частью одного общего события.
