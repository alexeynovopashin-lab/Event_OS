# Purpose

Этот документ определяет долгосрочное направление развития Event OS.

Он является главным архитектурным документом проекта и отвечает на вопрос:

> **Почему существует Event OS и каким должен стать продукт через 10–15 лет.**

Все технические, дизайнерские и продуктовые решения должны соответствовать принципам, изложенным в данном документе.

---

# Product Definition

**Event OS** — контекстно-ориентированная операционная система для управления мероприятиями.

Мы не создаем CRM.

Мы не создаем Task Manager.

Мы не создаем ERP.

Мы не создаем бухгалтерскую систему.

Мы создаем цифровую операционную среду, объединяющую всех участников мероприятия вокруг одного события.

---

# The Problem

Сегодня организация мероприятий строится вокруг памяти организатора.

Самая важная информация находится одновременно:

- в голове организатора;
- в Telegram;
- в WhatsApp;
- в телефонных звонках;
- в PDF-документах;
- в таблицах;
- в календарях;
- в общих папках;
- в сообщениях подрядчиков.

Ни один участник проекта не обладает полной и актуальной картиной происходящего.

Каждый самостоятельно восстанавливает контекст.

Это приводит к ошибкам, недопониманию и постоянным уточнениям.

---

# Hidden Problem

Самая большая проблема индустрии — не отсутствие инструментов.

Самая большая проблема — потеря контекста.

Организатор обладает полной картиной проекта.

Все остальные обладают лишь отдельными фрагментами.

При изменении маршрута, времени или условий организатору кажется, что изменения очевидны для всех.

На практике подрядчики продолжают работать по устаревшей информации.

Фотограф проверяет Telegram.

Видеограф открывает общую папку.

Ведущий звонит организатору.

Каждый вынужден самостоятельно искать изменения.

---

# The Movie Principle

Большинство исполнителей подключаются к проекту уже после того, как подготовка идет несколько месяцев.

Они оказываются в ситуации, когда необходимо понять историю мероприятия, не имея возможности увидеть весь процесс подготовки.

Это похоже на просмотр фильма с середины.

Новый участник не знает:

- какие решения уже приняты;
- что изменилось;
- почему появились ограничения;
- какие договоренности уже существуют.

Event OS должна автоматически предоставлять необходимый контекст каждому новому участнику.

---

# Mission

Освободить внимание людей от организационного хаоса.

Люди должны создавать события.

Система должна управлять информацией.

---

# Core Philosophy

Event OS хранит не информацию.

Event OS хранит контекст.

Каждое изменение автоматически становится частью проекта.

Каждый участник получает только тот контекст, который необходим именно ему.

---

# Event First

Главная сущность платформы — **Event**.

Не пользователь.

Не компания.

Не клиент.

Не подрядчик.

Именно событие объединяет:

- людей;
- команды;
- документы;
- коммуникации;
- локации;
- маршруты;
- оборудование;
- статусы;
- историю;
- постпродакшен.

Все остальные сущности существуют только как элементы события.

---

# Single Source of Truth

В проекте существует только одна актуальная версия информации.

Любое изменение вносится один раз.

После этого система самостоятельно обновляет контекст всех заинтересованных участников.

Никому не требуется повторно пересылать информацию.

---

# Context Instead of Information

Наша задача — не показать пользователю максимум информации.

Наша задача — показать информацию, необходимую для следующего решения.

Контекст определяется четырьмя параметрами:

- роль пользователя;
- текущее время;
- этап мероприятия;
- изменения, влияющие на пользователя.

---

# Timeline Is The Product

Timeline — центральный интерфейс Event OS.

Это не календарь.

Не список задач.

Не расписание.

Timeline представляет собой живую модель события во времени.

Каждая сцена содержит собственный контекст.

Любая информация открывается через Timeline.

---

# Context Navigator

Event OS работает по принципу автомобильного навигатора.

Навигатор знает весь маршрут.

Но показывает только следующий необходимый шаг.

Event OS знает весь проект.

Но показывает только информацию, необходимую пользователю именно сейчас.

---

# Navigator Principles

Пользователь не ищет информацию.

Информация приходит к пользователю.

Пользователь не изучает проект.

Проект сопровождает пользователя.

Пользователь не открывает десятки экранов.

Он движется по Timeline.

---

# Rescue Room Principle

Каждый участник получает собственную "выручай-комнату".

При открытии проекта система автоматически отвечает на вопросы:

- Где я сейчас?
- Что происходит?
- Что изменилось?
- Что мне необходимо сделать?
- Что произойдет дальше?

Каждый видит только ту часть проекта, которая относится к его текущей работе.

---

# Human Attention

Самый ценный ресурс проекта — внимание человека.

Главная задача Event OS — защищать внимание пользователя.

Любая новая функция должна уменьшать когнитивную нагрузку.

Если функция требует от пользователя помнить больше информации, значит она противоречит философии продукта.

---

# Human Control

Любое окончательное решение принимает человек.

Платформа никогда не действует самостоятельно.

Она может:

- предупреждать;
- объяснять;
- рекомендовать;
- подготавливать действия.

Она не должна самостоятельно изменять проект.

---

# Artificial Intelligence

ИИ является дополнительным уровнем системы.

Он не является обязательным компонентом.

При отключении ИИ вся функциональность платформы сохраняется.

ИИ усиливает работу с контекстом, но не создает его.

---

# Platform Vision

Через несколько лет Event OS должна стать единым цифровым пространством для всей event-индустрии.

Организатор.

Фотограф.

Видеограф.

Ведущий.

Флорист.

Ресторан.

Музыканты.

Клиенты.

Все работают внутри одной системы, используя единый источник данных.

---

# Success Criteria

Мы считаем продукт успешным, когда:

- организатор перестает быть единственным носителем информации;
- новый участник понимает проект за несколько минут;
- изменения автоматически доходят только до тех людей, которых они касаются;
- пользователи перестают искать информацию в мессенджерах и папках;
- интерфейс сопровождает пользователя через событие, подобно навигатору;
- люди концентрируются на мероприятии, а не на управлении информацией.

---

# North Star Statement

> **Event OS — это контекстно-ориентированная операционная система, которая сопровождает каждого участника мероприятия, предоставляя правильную информацию в правильный момент времени.**

Мы не автоматизируем мероприятия.

Мы освобождаем внимание людей.

Мы не управляем людьми.

Мы управляем контекстом.
